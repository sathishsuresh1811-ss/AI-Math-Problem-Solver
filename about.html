Project Overview & Objectives
College Capstone Project: AI Math Problem Explainer and Error Checker

The primary goal of this application is to scientifically investigate how reliably modern AI models solve school and college mathematics, how different prompt engineering techniques affect reasoning fidelity, and whether autonomous self-verification prompts improve accuracy or induce cognitive confirmation bias.

Responsible AI & Mathematical Research Quality Principles
Mandatory scientific guidelines for evaluating artificial intelligence in educational mathematics
1. AI Fallibility in Arithmetic

Large Language Models are probabilistic next-token predictors, not formal computer algebra systems. They can and do make arithmetic slips, sign inversions, and domain violations.

2. Decoupling Answers from Derivations

A correct final answer does not imply correct reasoning (compensatory errors can accidentally yield the right number), and an incorrect final answer often contains valid intermediate steps.

3. Sampling & Prompt Sensitivity

Model checkpoints, sampling temperature (temperature = 0.1 was used here), system instructions, and minute phrasing changes can substantially alter mathematical derivations.

4. Verifiable Model Versioning

All benchmarked trials explicitly record the exact model identifier (e.g. demo-baseline-v1.0, gpt-4o-mini) and timestamp to guarantee reproducible research comparisons.

5. Sample Size Limitations

One run per question is an exploratory comparative indication, not an unconditional statistical proof of general capability. Multiple trials and statistical margins must be reported.

6. Human-in-the-Loop Review

For ambiguous mathematical formatting, non-standard notation, or high-stakes examinations, automated parsers must route records to human mathematical evaluators.

7. Explanations != Mathematical Proof

Natural language explanations produced by AI systems must not be treated as mathematical proofs without external validation through Computer Algebra Systems or formal verification.

8. Separation of Baseline & Live Data

Local deterministic demo solvers are clearly labeled as baseline benchmarks and never falsely attributed to commercial proprietary models.

Live API Configuration Guide
How to connect commercial AI providers for live evaluations

The application runs 100% out of the box in demo baseline mode without requiring any paid API keys. To enable live evaluations with ChatGPT, Google Gemini, or Claude, configure the environment variables in a .env file in the project root:

# OpenAI ChatGPT Configuration
OPENAI_API_KEY=sk-proj-your-openai-key-here
OPENAI_MODEL=gpt-4o-mini

# Google Gemini Configuration
GEMINI_API_KEY=your-gemini-api-key-here
GEMINI_MODEL=gemini-1.5-flash

# Anthropic Claude Configuration
ANTHROPIC_API_KEY=sk-ant-your-anthropic-key-here
ANTHROPIC_MODEL=claude-3-5-haiku-20241022
